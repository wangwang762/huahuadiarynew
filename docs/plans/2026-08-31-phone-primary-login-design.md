# 花花日记本手机号主登录设计

## 目标

登录页改为手机号验证码优先，邮箱验证码作为备用入口，游客仍可跳过并把数据保存在本机。手机号与邮箱不能被当作两个独立花园；正式账号以后统一以 CloudBase UID 作为数据归属，备用邮箱需要在已登录账号中完成关联。

## 登录体验

默认展示中国大陆手机号输入，发送六位短信验证码后进入花园。用户可切换到“使用邮箱登录”，沿用现有邮箱验证码流程。两个入口共享同一套手账视觉、验证码格、倒计时、错误提示和自动提交逻辑。切换方式时清空上一次的验证码与错误，避免把手机号验证码误用于邮箱。

开本动画只在本次进入 App 的首次登录页出现一次。游客跳过后从账号入口回来、正式账号退出后回到登录页，以及手机号和邮箱之间切换时，都直接展示已经打开的登录纸页，不再重播封面动画。减少动态效果模式继续直接显示最终状态。

## 账号关系

手机号和邮箱在 CloudBase 中只有经过账户关联后才共享同一 UID。MVP 不以字符串匹配、前端 localStorage 或业务表合并伪造绑定关系。登录页允许两种已存在的身份登录；账号页后续提供绑定状态与补绑入口，通过 CloudBase 的 `sudo`、`verify`、`bindPhoneNumber` 或 `bindEmail` 完成安全关联。

## 用户管理

一期不另做管理后台。账号、登录方式和封禁状态在 CloudBase 控制台“身份认证 → 用户管理”查看；植物和日记仍在 PostgreSQL 的 `profiles`、`plants`、`diary_entries` 中按 UID 管理。只有出现客服检索、内容治理、运营分析或批量操作需求后，再建立业务管理后台。

## 验收

手机号格式必须通过校验后才能发短信；手机号和邮箱都能进入六位验证码页；验证码错误、过期、频繁请求和网络异常有对应提示；游客跳过后再次点登录不重播动画；登录成功后的账号对象能同时识别手机号和邮箱字段；现有邮箱登录、游客本地数据和 CloudBase 数据测试继续通过。
