# 移动端相机直达与响应式外壳设计

## 目标

让花花日记本在真实手机浏览器中像一个 H5 应用，而不是把手机模型再次渲染进手机屏幕；同时把植物日记页的「拍照记录今天」改成直接唤起系统拍照，拍完自动进入 AI 观察，删除重复的照片确认步骤。

## 已确认交互

- 真实移动端隐藏模拟状态栏、灵动岛、外框和底部 Home Indicator，内容铺满可视区域，并使用系统安全区。
- 移动端内容最大宽度为 480px；超过该宽度时保持居中，避免平板上无限拉伸。
- 桌面端继续显示 390×844 的手机模型，作为设计稿预览。
- 植物日记页点击「拍照记录今天」后直接触发文件输入；移动端请求后置摄像头，桌面端打开图片选择器。
- 用户取消拍照时不跳页、不提示错误；选定照片后立即进入分析状态，不再显示「让花花看看」确认按钮。
- 上传或图片读取失败时保留可恢复路径，允许重新拍照；AI 识别结果页及健康/异常分流逻辑保持不变。
- 花大夫入口的陌生植物识别仍沿用现有流程，本次只删除“已有植物拍照记录”的冗余确认步骤。

## 技术方案

`IOSDevice` 增加稳定的 class，而不再依赖内联样式完成所有布局。CSS 在窄屏条件下把设备外壳变为 `min(100vw, 480px) × 100dvh`，去除圆角、阴影和模拟系统栏，并为应用内容暴露 `--app-safe-top`、`--app-safe-bottom`。桌面条件保持当前手机模型。

`PlantDiary` 持有隐藏的 `input[type=file]`，设置 `accept="image/*"` 和 `capture="environment"`。成功读取文件后以 data URL 传给 `go("capture", plant, { image })`。`CaptureFlow` 接收 `initialImage`，已有植物记录若有该图片则首屏直接执行分析；图片显示和 AI 请求都使用这张真实照片。无图片的花大夫入口继续保留现有拍摄/识别入口。

## 验收标准

在 320、375、390、430、480px 视口下不出现模拟状态栏和 Home Indicator，内容无横向滚动；在桌面视口下仍显示完整手机模型。点击拍照按钮只触发一次系统文件输入，取消后仍在植物日记页，选择图片后直接进入分析，AI 请求使用选择的图片，结果仍能保存进日记或轻量进入花大夫。
