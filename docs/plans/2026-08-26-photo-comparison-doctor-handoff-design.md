# 拍照记录、前后对比与轻问诊衔接设计

## 目标

把“拍照记录”设计成花花日记本的连续观察入口：每次拍照都优先与同一植物上一次可比较的照片对照；没有明显问题时直接记入日记，发现变化时仍先保存本次观察，再用不打断记录的方式邀请用户携带这张照片去问花大夫；问诊完成后把结论补回同一篇观察记录，形成一条连续的植物病历。

## 核心原则

记录是主线，问诊是支线。异常不意味着禁止保存，用户也不需要在“保存照片”和“去问诊”之间二选一。新照片一旦完成分诊，就应成为可持续比较的观察记录；问诊只是为这条记录补充解释和护理方案。

比较必须有证据。只有同一植物上一条包含真实拍摄快照的记录可以作为对照；没有上一张、上一张损坏、服务失败或模型把握不足时，展示“第一次观察”或“暂时无法比较”，不能伪造“变好”或“变坏”。

提醒保持克制。异常结果不使用大面积警告色、强制弹窗或把“去问诊”设成唯一主按钮；页面先描述变化，再提供主题色主按钮“记入日记”和较轻的文字动作“带着这张照片问问花大夫”。

## 主链路

### 正常状态

用户拍摄当前照片，客户端取同一植物最近一条带 `photoData` 的记录作为上一张，将当前图和上一张一起交给健康分诊。结果为 `good` 时，页面显示“和上次差不多，暂未看到明显异常”或“比上次舒展了一些”；主按钮为“记入日记”。保存后返回植物日记，当前照片成为下一次比较基线。

### 轻微或明显异常

结果为 `watch` 或 `sick` 时，页面先显示对比结论，例如“和上次相比，叶尖的焦黄多了一些”，下方以轻量提示补充“可以先记下来，也可以顺便问问花大夫”。主按钮仍为“记入日记”，次级动作是“带着这张照片问问花大夫”。

用户点击主按钮时，本次照片、可见变化、趋势和上一次记录 ID 一起存入日记，然后返回植物日记。用户点击问诊动作时，系统先静默保存同一条观察记录，再把当前照片、上一张照片、趋势和本次观察带入花大夫，避免重新上传和重复描述。

### 问诊结束

花大夫沿用当前照片作为问诊主图，并可使用上一张作为变化背景。问诊结束后不再另建一篇脱离上下文的诊断记录，而是在本次观察记录中补充 `diagnosis`，包括症状、结论、护理方案、复查天数、紧急程度和模型置信度。时间线上的同一张卡片由“观察记录”升级为“观察 + 花大夫建议”。历史独立诊断记录继续兼容显示，不做迁移。

## 比较规则

比较输入包括当前照片 `currentImage`、最近一次有效观察照片 `previousImage`、植物品类、当前记录时间与上次记录时间。服务输出固定为 `better`、`same`、`worse`、`unknown` 四种趋势，并同时返回健康等级、当前可见现象、与上次相比的变化描述、可能原因和置信度。

当没有上一张有效照片时，趋势必须为 `unknown`，文案使用“第一次留下健康基线”。当模型无法可靠比较或请求失败时，不得降级为健康，而是保留当前照片并提示“这次暂时无法可靠比较，可以重拍或先记下来”。

趋势和健康等级是两个维度：植物可以“仍然有问题但比上次好转”，也可以“目前尚可但比上次略差”。路由主要由健康等级决定，趋势只负责连续观察文案，避免把“好转”误写成“已经健康”。

## 数据模型

观察记录继续使用 `kind: "record"`，新增以下字段：

```js
{
  photoData: "data:image/jpeg;base64,...",
  observedAt: "2026-08-26T10:00:00.000Z",
  comparison: {
    previousEntryId: "plant-rec-previous",
    trend: "better|same|worse|unknown",
    summary: "叶尖焦黄范围比上次扩大",
    health: "good|watch|sick",
    observations: ["叶尖焦枯", "局部黄斑"],
    likelyCause: "可能与盆土长期偏湿有关",
    confidence: 0.82
  },
  doctorStatus: "not_needed|suggested|started|completed",
  diagnosis: null
}
```

问诊完成后只更新这条记录的 `doctorStatus` 和 `diagnosis`。登录用户通过现有 `diary_entries.data` JSON 字段持久化，不需要新增数据库列；游客继续写入本地花园。为控制本地存储体积，日记快照使用最长边 720px、JPEG 质量 0.72，分诊请求可以继续使用最长边 960px 的临时图片。

## 界面层级与文案

照片仍是页面视觉中心，照片下先出现一行短趋势结论，再出现一张低对比度的观察卡。正常状态只显示“记入日记”；异常状态的主按钮也保持“记入日记”，其下用文字按钮显示“带着这张照片问问花大夫”，不使用铃铛、红色整块背景或“必须就医”的语气。

建议文案映射如下：`better` 为“比上次舒展了一些”，`same` 为“和上次差不多”，`worse` 为“和上次相比，有些变化更明显了”，`unknown` 为“这是第一次观察”或“这次暂时无法比较”。健康提示使用“暂未看到明显异常”“有一点需要留意”“看起来不太舒服”，不使用“状态不错”覆盖模型看到的异常。

## 错误与边界状态

上一张照片不存在或损坏时只做单图分诊，并明确没有形成对比；当前照片处理失败时不保存空图片，允许重拍；分诊网络失败时允许把照片作为“待观察”记录保存，但不能生成健康结论；保存失败时停留当前页面并保留照片；问诊服务失败时观察记录已经安全保存，用户可从该日记卡片再次发起问诊。

## 验收标准

正常、轻微异常、明显异常、首次拍照、无可用上一张、分诊失败六条路径均可完成记录；第二次拍照请求包含前后两张真实图片；异常照片点击问诊前已保存且问诊页无需再次上传；结束问诊后同一条记录出现诊断内容且不重复新增诊断日记；游客刷新后仍可恢复图片与比较结论；所有主按钮保持花花日记本主题绿色。
