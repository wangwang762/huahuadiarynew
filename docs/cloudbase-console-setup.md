# CloudBase 控制台配置清单

环境：`huahuadiary-d4gajnlumc8432f6c`  
地域：上海（`ap-shanghai`）

代码已经连接这个环境，但真实验证码和远端数据只有在下面配置完成后才能工作。不要把 SecretId、SecretKey、腾讯云密码或 SMTP 密码复制到前端代码或聊天中。

## 1. 开启手机号与邮箱验证码登录

进入 CloudBase 控制台，选择当前环境，然后进入“身份认证 → 登录方式”。开启“短信验证码”和“邮箱验证码／邮箱 OTP”，并允许不存在的手机号或邮箱在第一次验证后创建用户。前端默认显示中国大陆手机号，邮箱作为备用入口；真实短信会占用短信额度，不能把本地验证通过当成真实短信已经可用。

手机号与邮箱不会因为内容相似或属于同一个人而自动合并。CloudBase 会把两个独立登录行为视为两个身份，只有在同一个已登录 UID 下完成账号关联，才能共同访问同一份花园数据。本期账号页会明确显示手机号和备用邮箱的绑定状态；在关联流程上线并经过真实验证码验收前，不要让同一用户分别用手机号和邮箱创建两个账号。

## 2. 创建三个文档数据库集合

进入“数据库 → 文档数据库”，创建以下集合，名称必须完全一致：

- `profiles`
- `plants`
- `diary_entries`

本期查询只按 `ownerId` 过滤并在浏览器内排序，不需要创建复合索引。若控制台要求索引，为三个集合分别创建 `ownerId` 的普通索引即可。

## 3. 配置集合安全规则

分别打开三个集合的安全规则，把 [cloudbase-security-rules.json](../cloudbase-security-rules.json) 中对应集合的四条表达式复制进去。规则含义是：必须登录，创建时 `ownerId` 必须等于当前 CloudBase UID，之后只有这个 UID 可以读取、修改或删除该记录。

先在测试环境验证规则；不要为了图省事选择“所有用户可读写”。`profiles`、`plants` 和 `diary_entries` 中都可能包含用户邮箱或私人日记。

## 4. 添加 Web 安全来源

进入“环境设置／安全来源／Web 安全域名”，开发阶段添加本机预览来源 `http://127.0.0.1:4176` 和 `http://localhost:4176`；正式部署后再加入真实 HTTPS 域名，并删除不再使用的测试来源。如果控制台只接受域名、不接受协议或端口，则按界面提示分别填写 `127.0.0.1` 与 `localhost`。

## 5. 验证

正常打开 `花花日记本.html`，页面不应显示固定开发验证码。默认填写真实手机号后应收到六位短信验证码，也可以切换到邮箱验证码；验证成功的新用户进入空花园。添加第一盆植物后，刷新或更换设备用同一种已验证身份登录，植物与第一篇日记仍应存在。开门动画只在当前 App 会话首次进入登录页时播放，从游客账号点击登录或退出账号返回登录时应直接显示表单。

## 6. 管理用户

MVP 不需要另做一套用户管理后台。进入 CloudBase 控制台的“身份认证 → 用户管理”即可查看 UID、手机号／邮箱身份、创建时间和最近登录时间；业务侧的植物、日记和照片继续在 PostgreSQL 表中按 ownerId 查询。只有在需要封禁、人工合并账号、客服检索和运营分群时，再增加受管理员权限保护的内部后台。

若需要继续看 26 盆设计样例，使用 `花花日记本.html?demo=1`。这个模式完全使用本地演示数据，不会写入 CloudBase。
