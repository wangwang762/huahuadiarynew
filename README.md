# Handoff: 花花日记本(Huahua Plant Diary)

## Overview
「花花日记本」是一款以**拍照记录为核心**的植物养护陪伴 App。用户给自己的盆栽拍照,AI 为每株植物生成统一画风的**可爱卡通形象**、判断健康状况、并以植物的**性格口吻**写成日记。内置「花大夫」情绪化问诊诊所、按品种的养护知识库,以及可切换样式/配色的 iOS 桌面小组件。

本交接包包含:
- **可点击高保真原型**(HTML/React-in-Babel)——展示完整界面与交互
- **《产品逻辑与 AI 方案》文档**——补齐原型未实现的智能/知识/API 层,含**可直接使用的提示词模板**

---

## About the Design Files
**本包内的 HTML 文件是用 HTML + 浏览器内 React(Babel)制作的「设计参考稿」**,用于呈现预期的外观与交互行为,**不是可直接照搬上线的生产代码**。

任务是:在目标代码库的现有技术环境中(本项目目标平台为 **iOS,建议 SwiftUI**)**重建**这些设计,沿用该环境既有的组件、模式与库。原型中的"AI 实时对话/分流/生图"等行为,应理解为**需要在真实 App 里按《产品逻辑与 AI 方案》文档落地的服务端能力**,而非把 HTML 直接打包。

> ⚠️ 重要:原型里的卡通植物形象目前是**预制透明 PNG**(开发期用 canvas 插画引擎生成)。**iOS 上架后不可在端上跑该引擎**——必须改为**服务端生成**(建档时一次性调用生图 API,成品存 CDN,端上直接显示)。详见方案文档第 01 节。

## Screens / Views

### 1. 日记本首页(Home / 日记)
- **Purpose**:植物聚集地。双列等高卡片展示所有植物的日记封面,点击进入该植物档案。
- **Layout**:顶部沉浸式天气头(左上城市定位 + 右上天气),下方标题区,再下方 2 列 CSS Grid 卡片(`gap` 间距,等高)。底部三 Tab 导航。
- **Components**:
  - **天气头**:当前城市(左上)、天气图标+温度(右上)、晴/多云/小雨的氛围动画(阳光束/云层/雨丝)。
  - **植物封面卡**:封面照片(透明 PNG 卡通形象,植物主题色渐变底,`object-position: 50% 14%` 偏上裁切防切头)、植物名、最近一篇日记摘要。`warn` 状态有视觉提示。
  - **Tab 切换**:全部 / 需照料(点击筛选)。
- **关键修复点**:封面背景用各植物主题色淡色渐变;高瘦植物按比例缩放避免裁切顶部。

### 2. 植物档案(Plant Profile / 档案)
- **Purpose**:单株植物的主页:简介(照片+养护指南+性格)、日记流。
- **Layout**:顶部植物简介模块(照片、养护指南可展开、性格特点融入头部),性格调整入口放在第一模块卡片上(低调)。中部数字融入头部构成"植物简介"。底部露出至少一篇日记。一个主按钮。
- **养护指南**:默认**完全收起**,仅留一个展开入口;展开后是该植物**第一人称**口吻的养护说明(由知识库转写)。

### 3. 花大夫问诊(Doctor Chat)
- **Purpose**:情绪化的植物诊所。多轮对话问诊,用户主动结束后总结入日记。
- **Layout**:顶部返回 + 医生头像上下文条,中部对话气泡流,底部输入框 + 快捷回复。
- **关键交互**:
  - 对话进行中**不打断**(不中途弹保存卡)。
  - 出现 ≥1 条医生回复后,流中央显示**绿色描边款**「结束问诊 · 记入日记」按钮(浅绿底 `var(--green-soft)` + `1.5px solid var(--green)` + 绿字),低调不抢眼。
  - 点击后推送**总结卡片**(绿色对勾、"已记入 XX 的日记"、本次养护要点),下方「查看所有日记 →」按钮跳回首页。结束后输入框与快捷回复收起。
  - **诊所墙**:张贴历史问诊记录,可见上次咨询了哪些植物及近况。
- **预设分支**(诊所内拍照):识别为已入库 → 复诊;全新植物 → 先诊断再建档;同品种疑似新个体 → 询问用户确认。详见方案文档第 03 节。

### 4. 桌面小组件(Widget Styles)
- **Purpose**:展示可切换的 iOS 小组件样式 + 配色。
- **Layout**:顶部**尺寸分页器**(正方形 ↔ 长方形,横向 snap 滚动,右侧露出下一个作隐喻),分页器外框背景**呼应选中配色**。下方花园版样式;再下方**配色控件**(色板与对应背景的明度/饱和度一致)。
  - 卡片格子**贴合卡片自身宽度**(非固定百分比),正方形不留多余白边,两卡紧挨,`gap` 较小。
- **正方形(对应 iOS 小号 2×2,比例 1:1,232×232)**:**单株「今日出镜」**——随机轮换一盆,顶部为植物名(无徽章/性格标签),下方加宽区域显示该植物**第一人称心灵鸡汤**(性格化,最多 4 行),植物立于右侧小窗台。
  - 阳台风格背景、天光投影、植物坐于木架上(架子离底部留空)。
  - **小动物**:蝴蝶/蜜蜂/小鸟偶尔飞过停在花/叶上再飞走(频率低);蝴蝶为温和暖橙双翼振动样式。
- **长方形(对应 iOS 中号 4×2,比例≈2.1:1,320×152)**:全家福——展示所有植物 +「N 盆 · 都还活着」。
- **天气联动**:晴(暖阳光束,光芒以右上太阳为中心放射)、多云(连续整片云层、各云不透明度不同、线性无缝左→右漂移)、小雨(雨丝)。

### 5. 新手引导(Onboarding)
- **Purpose**:零数据冷启动。引导拍第一张照片 → 填昵称(品种由 AI 自动识别)→ 生成第一篇日记(带炫酷动效 + 情感化文案)。

## Interactions & Behavior
- **导航**:三 Tab(日记本 / 花大夫 / 小组件),history 栈式路由(见 `app.jsx`)。
- **分流**:拍照后由健康识别结果 `route` 驱动:`record`(温情记录)/ `soft_hint`(记录 + 弱弱提示看医生)/ `diagnose`(引导问诊)。详见方案文档第 02 节决策树。
- **动效**:小组件植物 sway 摇摆(按物理特性:仙人掌轻微、绿萝强烈,统一方向);天气氛围动画;问诊总结卡上浮;入场动画以可见终态为 base,从隐藏态 animate-in,`prefers-reduced-motion` 与打印时显示终态。
- **分享**:植物档案右上角分享 → 生成「成长小报 × 成长相册」**融合版**单图(一屏内,iPhone 相册式缩略图布局,标注天数),分享按钮置于小报下方、整体居中。

## State Management
- 路由栈(当前屏 + 参数)、`hh-onboarded`(localStorage,是否已过引导)、各植物 `health` 状态、问诊会话 `convo` / `typing` / `finished`、小组件 `sizeIdx` / 选中配色 / 选中样式。
- 真实 App 中:植物列表、日记流、问诊记录、天气、知识库检索结果需后端拉取(见方案文档第 07 节数据结构)。

## Design Tokens
**字体**
- 衬线日志体(标题/日记):`--f-journal`(思源宋体 / Noto Serif SC 类)
- 手写体(点缀):`--f-script`
- 正文:同上宋体族

**主色(绿色主题,源自养护/医生语境)**
- 主绿 `--green` `#2C6147`
- 深绿 `--green-deep` `#1d4a34`
- 浅绿底 `--green-soft`、绿气泡 `--green-bubble`
- 墨色文字 `--ink` `#2b2a26`,次级 `--ink-soft` `#55524b`,弱 `--ink-faint` `#8a857c`
- 纸感背景米色系;发丝线 `--hairline`

**圆角**:`--r-pill`(胶囊)、`--r-lg`(卡片大圆角)等(见 `styles.css`)
**阴影**:`--sh-1` / `--sh-2`(柔和投影)

## 实现建议(给开发者)
1. 先搭**服务端编排层**,统一封装"拍照 → 识别 → 分流 → 生文案/生图"主链路。
2. 知识库先覆盖原型里这几种(仙人掌/多肉/绿萝/龟背竹/向日葵)再扩。
3. 生图先跑通一种品种打样,确认画风一致性达标再批量。
4. 客户端按方案文档的**分流决策树**接服务端返回的 `route` 字段。
5. iOS 小组件用 WidgetKit 实现,正方形/长方形对应 systemSmall / systemMedium。
